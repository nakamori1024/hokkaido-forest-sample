# 北海道 林小班区画及び森林資源データ Portolan 版 データ仕様

- 準拠：[Portolan 仕様](https://github.com/portolan-sdi/portolan-spec) v0.2.0（STAC 1.1.0 の静的カタログ、GeoParquet、PMTiles）
- 元データ：北海道「森林計画関係資料オープンデータ」のうち「林小班区画及び森林資源データ」の 2 年分

  - 令和6年末現在（`y2024`）
- 位置づけ：北海道が作成したデータを、第三者が Portolan の形式で再配布する**非公式コピー（mirror）**。北海道の公式な配布ではない

各節の決定の理由は [design-rationale.md](design-rationale.md) に、同じ章立てでまとめている。

## 1. 目的と範囲

北海道が Shapefile と Excel で配っている「林小班区画及び森林資源データ」を、クラウドネイティブな形式（GeoParquet・PMTiles）と STAC のメタデータで配り直すための仕様を定める。

- 対象は「林小班区画及び森林資源データ」だけ。同じページの kmz、QField 用データ、森林資源構成表、齢級別伐採量は対象外（理由：[対象のデータ](design-rationale.md#対象のデータ)）
- Shapefile と Excel は配らない。データ本体は GeoParquet と Parquet、表示用は PMTiles（理由：[配る形式](design-rationale.md#配る形式)）
- 北海道とは別の者がホストする mirror として作る（理由：[非公式のコピーとして作る](design-rationale.md#非公式のコピーとして作る)）

## 3. カタログの構成

```
catalog/
├── catalog.json / README.md / AGENTS.md        年の一覧、年をまたぐ比較の注意
├── y2023/                                      令和5年末現在のサブカタログ（y2024 と同じ構成）
└── y2024/                                      令和6年末現在のサブカタログ
    ├── catalog.json / README.md / AGENTS.md
    ├── subcompartments/                        小班（GeoParquet の collection）
    │   ├── collection.json / README.md / AGENTS.md
    │   ├── subcompartments.parquet
    │   ├── subcompartments.pmtiles
    │   ├── styles/default.json
    │   └── thumbnail.png
    ├── compartments/                           林班（GeoParquet の collection）
    │   └── （subcompartments と同じ構成）
    ├── stand_layers/                           層（表データの collection）
    │   ├── collection.json / README.md / AGENTS.md
    │   └── stand_layers.parquet
    ├── codes/                                  森林簿コード（表データの collection）
    │   ├── collection.json / README.md / AGENTS.md
    │   └── codes.parquet
    └── municipalities/                         振興局・市町村（表データの collection）
        ├── collection.json / README.md / AGENTS.md
        └── municipalities.parquet
```

- **年のサブカタログ**：`y` ＋ 西暦 4 桁（例：`y2024`）。西暦はデータの時点（「令和6年末現在」なら 2024）。会計年度ではない。サブカタログの `title`（例：「令和6年（2024年）末現在」）と、collection の時間の範囲（例：2024-12-31）でも時点を示す（理由：[年のサブカタログ](design-rationale.md#年のサブカタログ)、[年のサブカタログの名前](design-rationale.md#年のサブカタログの名前)）
- **振興局では分けない**：全道を 1 ファイルにし、振興局はコードの列で持つ。全道で小班 約 210 MB、林班 約 30 MB で、分割は要らない（理由：[振興局で分けない](design-rationale.md#振興局で分けない)）
- **collection の ID ＝ ファイル名**（例：`y2024/subcompartments` の `subcompartments.parquet`）
- **表データの collection**（stand_layers・codes・municipalities）は、Portolan の決まりにより Parquet を 1 つだけ collection 単位の asset（role `data`）として持ち、item は持たない。PMTiles・サムネイル・スタイルは持たない
- codes と municipalities も年ごとに置く。コード表や市町村は改訂・合併で変わりうるので、「その年のデータは、その年の codes・municipalities で読む」ことにする（理由：[年ごとのコード表と市町村の表](design-rationale.md#年ごとのコード表と市町村の表)）

### 表どうしの結合

| 結合 | 結合に使う列 | 対応 |
|---|---|---|
| 小班 ↔ 層 | `小班キー` | 1 対多 |
| 小班 ↔ 林班 | 小班側の `left(小班キー, 10)` ＝ 林班側の `林班キー` | 多対 1 |
| 層 ↔ codes | 層の各コードの列 ＝ `コード`、かつ `区分` ＝ その列の区分名 | 多対 1 |
| 小班・層 ↔ municipalities（市町村） | `振興局コード` ＋ `市町村コード` | 多対多（旧市町村の行があるため。5.5） |
| 小班・林班 ↔ municipalities（旧市町村） | `振興局コード` ＋ `市町村コード`、かつ `left(林班, 1)` ＝ `林班開始番号` | 多対 1 |

## 4. 列の共通の規則

- **列名**：元データの見出し（日本語）のまま。振興局によって見出しが違う列は、PDF の「森林資源データの掲載項目」の名前にそろえる（`支庁コード` → `振興局コード`、`立地距離` → `立地距離コード`）（理由：[列名](design-rationale.md#列名)）
- **キーの列名**：小班のキーは `小班キー`（14 桁）、林班のキーは `林班キー`（10 桁）。元データでは shp の `キー`、調査簿の `KEYCODE`（理由：[キーの列名](design-rationale.md#キーの列名)）
- **コードの値**：固定桁の 0 埋め文字列（例：振興局 `08`、林班 `0066`、樹種 `01`）。調査簿では数値で、先頭の 0 が落ちているので補う（理由：[コードの値の型](design-rationale.md#コードの値の型)）
- **座標系**：JGD2000 の経緯度（EPSG:4612）。北海道では JGD2011・WGS84 と座標値が同じ（PROJ の変換が恒等変換）。GeoParquet の geo メタデータ（PROJJSON）と STAC の `proj:code` に書く（理由：[座標系](design-rationale.md#座標系)）
- **空欄**：値のないセルは null。ただし `複層区分コード` と `混植サイン` の空欄は 0 に置き換える（PDF でも空欄と 0 が同じ意味）（理由：[空欄を0にする列](design-rationale.md#空欄を0にする列)）
- **列の説明**：各 collection の collection.json に STAC の `table:columns` で、全列の説明を書く。null の意味（PDF の定義と、定義がなく推測したもの）を書き分ける（理由：[空欄の意味の書き方](design-rationale.md#空欄の意味の書き方)）

## 5. 各 collection の列

列は両年で同じ。ただし y2023 では、林班の `土保フT` と層の `代表地番` がない（12 節）。

### 5.1 subcompartments（小班）

GeoParquet。**1 行 ＝ 1 小班**。小班の shp の列と形状に、最下層の主な属性を足したもの（理由：[小班と層を分ける](design-rationale.md#小班と層を分ける)）。

| 列 | 型 | 元データ | 説明 |
|---|---|---|---|
| 小班キー | string（14 桁） | 小班 shp `キー` | 振興局 2 ＋ 市町村 2 ＋ 枝番 2 ＋ 林班 4 ＋ 小班 4。一意。層の表との結合キー |
| 振興局コード | string（2 桁） | 小班 shp `振興局` | 小班キーの 1〜2 桁目から作る |
| 市町村コード | string（2 桁） | 小班 shp `市町村` | 振興局の中での番号。小班キーの 3〜4 桁目から作る |
| 枝番 | string（2 桁） | 小班 shp `枝番` | 小班キーの 5〜6 桁目から作る。y2024 は全件 `00`、y2023 は「0 ＋ 林班の千の位」（12 節） |
| 林班 | string（4 桁） | 小班 shp `林班` | 小班キーの 7〜10 桁目から作る |
| 小班 | string（4 桁） | 小班 shp `小班` | 小班キーの 11〜14 桁目から作る |
| GIS面積 | double（ha） | 小班 shp `GIS面積` | まとめた形状から計算し直した面積（6 節）。分かれた小班では元の shp の値と異なる。形状がない小班は null |
| 最下層林種 | string | 調査簿 `林種コード` | 最下層の林種の**名称**（codes の表記） |
| 最下層樹種1 | string | 調査簿 `樹種1コード` | 最下層の主な樹種の**名称**（codes の表記）。林種が伐採跡地・未立木地（4・5・6）では null |
| 最下層林齢 | int16 | 調査簿 `林齢` | 最下層の林齢 |
| 層の数 | int8 | （導出） | その小班の層の行の数。単層林は 1 |
| geometry | MultiPolygon | 小班 shp | すべて MultiPolygon。形状がない小班は null |
| bbox | struct | （導出） | GeoParquet 1.1 の covering 列（xmin・ymin・xmax・ymax）。形状がない小班は null |

- **最下層**：単層林はその層、複層林は `複層区分コード` ＝ 1 の層。道の統計（林種・樹種・林相別森林資源構成表、北海道林業統計）と同じ規則。複層林の最下層は樹下植栽された下木であることが多く、上から見える林冠とは限らない（理由：[最下層を代表の層にする](design-rationale.md#最下層を代表の層にする)、[最下層の列名](design-rationale.md#最下層の列名)）
- 北海道林業統計 下巻 表30 の注 3 には「複層林は上層木を対象としている」とあるが、統計の値は実データでは最下層の規則と一致し、注と合わない。理由はわからない
- 最下層の属性は名称だけを持つ。コードが必要なときは層の表と結合する（11 節）（理由：[最下層の属性は名称だけ](design-rationale.md#最下層の属性は名称だけ)）
- 齢級・林相・蓄積は持たない。計算のしかたを README に書く（11 節）（理由：[導出した値を持たない](design-rationale.md#導出した値を持たない)、[層の数](design-rationale.md#層の数)）
- 振興局〜小班の分解した列は、shp の列ではなく小班キーから作る（理由：[分解した列](design-rationale.md#分解した列)）
- 林班キーの列は持たない。林班と結合するときは `left(小班キー, 10)` を使う（理由：[小班の表に林班キーを持たない](design-rationale.md#小班の表に林班キーを持たない)）

### 5.2 compartments（林班）

GeoParquet。**1 行 ＝ 1 林班**。林班の shp の列（年によってある列は 12 節）を持つ（理由：[林班の表の列](design-rationale.md#林班の表の列)）。

| 列 | 型 | 元データ | 説明 |
|---|---|---|---|
| 林班キー | string（10 桁） | 林班 shp `キー` | 振興局 2 ＋ 市町村 2 ＋ 枝番 2 ＋ 林班 4。一意 |
| 振興局コード | string（2 桁） | 林班 shp `振興局` | 林班キーから作る |
| 市町村コード | string（2 桁） | 林班 shp `市町村` | 林班キーから作る |
| 枝番 | string（2 桁） | 林班 shp `枝番` | 林班キーから作る |
| 林班 | string（4 桁） | 林班 shp `林班` | 林班キーから作る |
| TEXT | string（元の型のまま） | 林班 shp `TEXT` | ラベル用の林班番号。元データでは全件 `林班` と同じ値 |
| RINLBL | int64（元の型 Integer64 のまま） | 林班 shp `RINLBL` | ラベル用の林班番号（整数、先頭の 0 なし）。元データでは全件 `林班` の整数と一致 |
| 土保フT | string | 林班 shp `土保フT` | `（土保）` または null。**定義は道の資料に見つからない**（10 節）。y2023 にはない |
| geometry | MultiPolygon | 林班 shp | すべて MultiPolygon |
| bbox | struct | （導出） | GeoParquet 1.1 の covering 列 |

| 市町村コード | string（2 桁） | 振興局の中での番号 |

## 6. 形状の処理

小班・林班の形状は、両年とも次の順で処理する。

1. **面にならないリングを除く**：点が 4 つ未満のリングだけを除き、残りの部分を使う。すべてのリングがそうだった小班は、形状が null になる（理由：[面にならないリングと不正な形状](design-rationale.md#面にならないリングと不正な形状)）
2. **不正な形状を直す**：自己交差などで不正な形状は、GEOS の `make_valid` で直す
3. **同じキーの地物をまとめる**：同じ `キー` の地物を融合（union）し、1 行にする。接している部分は境界が消えて 1 つの面になり、重なっている部分は 1 回分になる（理由：[同じキーの地物を融合する](design-rationale.md#同じキーの地物を融合する)）
4. **型をそろえる**：部分が 1 つのものも含め、すべて MultiPolygon にする（GeoParquet の `geometry_types` は `["MultiPolygon"]`）（理由：[すべてMultiPolygonにする](design-rationale.md#すべてmultipolygonにする)）
5. **GIS面積を計算し直す**（小班）：まとめた形状から、すべての小班で、振興局ごとの元の平面直角座標系（年ごとの `.prj` に従う。11 節）で計算する（ha、小数 4 桁 ＝ 1 m² に丸める）（理由：[GIS面積を計算し直す](design-rationale.md#gis面積を計算し直す)）
6. **経緯度にする**：EPSG:4612 に換算する。座標は丸めない（理由：[座標を丸めない](design-rationale.md#座標を丸めない)）
7. **換算で不正になった形状を直す**：換算したあとに `make_valid` をかける

まとめても形状がない小班は、形状を null にして行を残す（`GIS面積`・`bbox` も null）。元データでも、小班の shp のキーと調査簿の KEYCODE は過不足なく一致する（理由：[形状がない小班](design-rationale.md#形状がない小班)）。

年ごとの件数：

| 処理 | y2024 | y2023 |
|---|---:|---:|
| 1. 面にならないリングを除いた小班 | 35 小班（41 本） | — |
| 2. `make_valid` で直した小班（元の座標系） | 0 件 | 323 小班 |
| 3. 融合した小班 | 3,092 小班 | 137,524 小班 |
| 3. 融合した林班 | 1 林班 | 169 林班 |
| 7. 換算で不正になり直した小班 | 7 小班 | — |
| 形状が null の小班 | 0 件 | — |

- 「—」は 10 節の変更の一覧に挙げていない項目
- y2024 で形状がない小班が 0 件なのは、元の shp で欠損していた地物が、どれも同じ小班のほかの地物に形状があったため
- y2023 の融合は、元の shp が離れた部分を別の地物にしていたもので、すべて離れた部分どうし（重なりも接する境界もない）。形状は変わらない

y2024 の分かれていない小班（871,892 件）で、計算し直した `GIS面積` と元の shp の値の差は、絶対値の中央値 0.0025 ha、0.01 ha 以内が 99.95%。0.1 ha を超えるのは 35 件で、最大は +1.5679 ha（`09060000330013`。元の値 0.14 ha が形状の面積と合っていない）。README に書く。

## 9. PMTiles・スタイル・サムネイル

小班と林班の collection に、表示用の PMTiles を付ける（Portolan の Visualization の MUST。GeoParquet が大きく、そのままでは描けないため）。表データの collection には付けない（理由：[PMTilesの範囲と属性](design-rationale.md#pmtilesの範囲と属性)）。

| 項目 | 小班（subcompartments） | 林班（compartments） |
|---|---|---|
| レイヤ名 | `subcompartments` | `compartments` |
| 入れる属性 | 形状と bbox 以外の全列（11 列） | 形状と bbox 以外の全列（y2024 は 8 列。y2023 は `土保フT` がない） |
| ズーム | 11〜14 | 7〜14 |
| 既定のスタイル（`styles/default.json`） | `最下層林種` で塗り分け（人工林・天然林・伐採跡地・未立木地）。拡大すると `林班-小班` の番号を表示 | 境界線と、`RINLBL`（林班番号）のラベル |
| サムネイル（`thumbnail.png`） | 既定のスタイルで全道を描いた画像 | 同左 |

理由：[ズーム](design-rationale.md#ズーム)

- PMTiles は collection 単位の `rel: "pmtiles"` リンク（web-map-links 拡張 v1.3.0、`pmtiles:layers` にレイヤ名）と、`visual` の role の asset の両方で登録する
- スタイルは MapLibre GL のスタイル（v8）の自己完結した JSON。`style` の role の asset として登録する。source の名前は collection の名前（`subcompartments`・`compartments`）にし、その `url` は `styles/` からの相対パス（例：`pmtiles://../subcompartments.pmtiles`。MapLibre GL JS の pmtiles プロトコルで読む）にする（理由：[色とsourceの名前](design-rationale.md#色とsourceの名前)）
- スタイルの `url` の相対パスは、公開時にも絶対 URL に書き換えない。MapLibre GL JS も pmtiles のプロトコルも、この相対パスをスタイルの URL を基準には解決しない（表示しているページの URL を基準にしてしまう）。そのため各 collection の README の `styles/default.json` の説明に、相対パスはスタイルのファイルが基準であること、MapLibre はそれを自動では解決しないこと、スタイルを取得して相対パスを絶対 URL に直してから渡すコード例を書く（理由：[スタイルの相対パス](design-rationale.md#スタイルの相対パス)）
- 小班の色：人工林 `#1f8a70`、天然林 `#9ccc65`、伐採跡地 `#e8a33d`、未立木地 `#b0a99f`。林班の境界線はこげ茶。小班の境界線はズーム 13 から、`林班-小班` のラベルは 15 から、林班番号は 12 から表示する
- `林班-小班` のラベルは、林班・小班とも先頭の 0 を除いて表示する（例：`0139`・`0502` → `139-502`）。値そのものは変えない（理由：[ラベル](design-rationale.md#ラベル)）
- ラベルのグリフは MIERUNE/fonts（`https://mierune.github.io/fonts/{fontstack}/{range}.pbf`）の `Noto Sans Regular` から読む

### 元データのままにした食い違い（y2024）

- **林班の表と結合できない小班**：胆振 29 林班（`0412000029`、39 小班）と石狩 3 林班（`0602000003`、9 小班）は、林班 shp にポリゴンがない。小班側（キー・調査簿）はそろっている。補わない（理由：[林班の表と結合できない小班](design-rationale.md#林班の表と結合できない小班)）
- **小班が 1 つもない林班**：58 件。実質的に重なる小班はなく、調査簿にもその林班キーの行がない。小班は林班のうち森林計画の対象になる森林の部分にだけ描かれていて、対象の森林がない林班と推測する
- **`土保フT` の意味**：定義が見つからない。上川（1,929 林班）で確かめると、林班の中に保安林（森林の種類 11〜19）や砂防指定地（32）の小班がある林班とよく重なるが、完全には一致しない（理由：[林班の表の列](design-rationale.md#林班の表の列)）
- **成長率の定義**：PDF に項目がない。値は割合と思われ、1 を超える値（`成長率N` の 4,125 行。`成長率L` は 0 行）はいずれも林齢 1〜5 年の若い林
- **調査簿の面積と GIS面積**：別の値（0.01 ha 以内で一致するのは 35%）

## 11. 利用者向けの説明（README・AGENTS.md）

README と AGENTS.md に、次の内容を書く。

### データの範囲と取扱の注意（README の冒頭）

- **範囲**：一般民有林（民有林のうち道有林を除いたもの）だけで、国有林と道有林は含まない。道有林のデータは道有林課のサイトで公開されている（理由：[範囲と取扱の注意](design-rationale.md#範囲と取扱の注意)）
- **取扱の注意**：元のページの「資料の取扱の注意」を、出典を示してそのまま載せる。実測ではなく地域森林計画樹立のため間接調査法により作成したもので、所有権等の諸権利、所有界、面積、木竹の評価等を証明するものではなく、現況と異なる場合がある、という内容

### 結合と集計の書き方

```sql
-- 小班に最下層のコードを付ける（1 小班に必ず 1 行が対応する）
SELECT s.*, l.林種コード, l.樹種1コード
FROM 'y2024/subcompartments/subcompartments.parquet' s
JOIN 'y2024/stand_layers/stand_layers.parquet' l
  ON l.小班キー = s.小班キー AND l.複層区分コード IN ('0', '1');

-- 層の表で面積を合計する（最下層に絞らないと二重計上になる）
SELECT 振興局コード, sum(面積)
FROM 'y2024/stand_layers/stand_layers.parquet'
WHERE 複層区分コード IN ('0', '1')
GROUP BY 1;

-- 名称を付ける
SELECT l.*, c.名称 AS 林種
FROM 'y2024/stand_layers/stand_layers.parquet' l
LEFT JOIN 'y2024/codes/codes.parquet' c
  ON c.区分 = '林種コード' AND c.コード = l.林種コード;

-- 林班ごとに集計する
SELECT left(小班キー, 10) AS 林班キー, sum(GIS面積)
FROM 'y2024/subcompartments/subcompartments.parquet'
GROUP BY 1;

-- 市町村名を付ける（旧市町村の行の重複を除いてから結合する）
SELECT s.*, m.市町村
FROM 'y2024/subcompartments/subcompartments.parquet' s
JOIN (SELECT DISTINCT 振興局コード, 市町村コード, 市町村
      FROM 'y2024/municipalities/municipalities.parquet') m
  USING (振興局コード, 市町村コード);
```

旧市町村との結合（`left(林班, 1) = 林班開始番号`）の SQL の例も書く。

QGIS の通常の結合（列どうしの一致）では、`left(小班キー, 10)` のような切り出しや、`区分` で絞った codes との結合ができない。仮想レイヤの SQL を使う。

### 道の統計と同じ値の計算のしかた

元データにない値は持たせないので、必要な利用者が計算する。次の規則は、道の「林種・樹種・林相別森林資源構成表」（令和6年）と調査簿を突き合わせて確かめたもの。成長量は、どの規則でも構成表の値を再現できなかった（総数で 0.3〜2.0% 多くなる）ので、計算のしかたを示さない。

| 値 | 計算のしかた |
|---|---|
| 面積 | 最下層（`複層区分コード` が 0 または 1）の行の `面積` の合計 |
| 齢級 | `least(ceil(林齢 / 5), 24)`。最下層の林齢を使う |
| 蓄積 | 全層の `面積 × (HA当蓄積N + HA当蓄積L)` の合計 |
| 林相（天然林） | 針葉樹の蓄積の割合 N / (N + L) を百分率で四捨五入し、75% 以上が針葉樹林、25% 以下が広葉樹林、その間が混交林。蓄積がない行は `樹種1コード`（39 / 99 / 98）で決める |

### そのほかの注意

- 令和6年末の渡島だけ、調査簿が 1 年成長させた値（シート名が「成長後」）で、林齢・蓄積が統計と 1 年ずれる。元データのままにしている（理由：[渡島の成長後の値](design-rationale.md#渡島の成長後の値)）
- 元の座標系（平面直角座標系の系）は、年ごとの元データの `.prj` に従う。面積や距離は、経緯度のままではなく、この系か測地線で計算する

  | 系 | EPSG | 令和6年末 | 令和5年末 |
  |---|---|---|---|
  | XI 系 | 2453 | 渡島・檜山・後志・胆振 | 渡島・檜山・後志 |
  | XII 系 | 2454 | 日高・石狩・空知・上川・留萌・宗谷 | 胆振・日高・石狩・空知・上川・留萌・宗谷 |
  | XIII 系 | 2455 | オホーツク・根室・釧路・十勝 | 同左 |

  胆振は年によって系が違う（令和5年末は `.prj`・注記のテキスト・座標値がそろって XII 系。令和6年末は `.prj` と座標値が XI 系で、注記のテキストだけ 12 系）
- 計画区は市町村ごとに決まる。番号は持たない
- 森林の種類など、調査簿の小班ごとに決まる値で地図を色分けするには、層の表と結合する必要がある（小班の表には最下層の林種・樹種1・林齢しかない）
- 層の表では、小班ごとに決まる値（計画区・面積・森林の種類など）が層の数だけ繰り返される

### 年をまたぐ比較の注意（ルートの README）

- codes・municipalities は、その年のものと結合する
- キーの枝番が年で違う。年をまたいで結合するときは、枝番を `00` にそろえる（小班キー：`left(小班キー, 4) || '00' || right(小班キー, 8)`、林班キー：`left(林班キー, 4) || '00' || right(林班キー, 4)`）
- キーが同じでも区画が同じとは限らない（形状が面積の 50% 超違う小班 5,973 件・0.7%、令和5年末の区画が別のキーの小班といちばん重なるもの 約 1,600 件・0.2%。道が区画を分割・統合・振り直したもの）
- 令和6年末の渡島は、林齢・蓄積が 1 年進んでいる
- 蓄積・成長率・樹高は、毎年計算し直される値
- 年によってない列（`代表地番`・`土保フT`）がある。年をまたいで読むときは `read_parquet([...], union_by_name = true)` とする
